Help & guides

          Launch Observer usage guide and best practices.
        

        
        
      

      

        
        
        
        
        
        
      

      

        


          

            

              
What this tool does

              
Launch Observer records the analytics requests a site sends while you browse it, decodes the payloads, and optionally checks each one against rules you supply. It is read-only: it never edits, blocks, or replays a request.

            

            

              
The three panes

              

                
SessionsRecordings grouped by site. One is active at a time.

                
RequestsCaptured calls, grouped by the page they fired on. Newest first.

                
DetailsQuery, payload, headers and raw body for the selected request.

              

            

            

              
Vocabulary

              

                
Site — a label you choose, such as Production or Staging. Allowlists and validation rules are stored per site.

                
Session — one recording window. Requests captured while it runs belong to it.

                
Allowlist — the domains worth capturing. Everything else is ignored, including by the page hooks.

                
Validation rules — an optional JSON file of checks run against each captured request.

              

            

            

              
Where your data lives

              
Everything stays in this browser's local extension storage. Nothing is uploaded, and the extension makes no network requests of its own. Use Manage data in the sidebar to see usage or clear it.

Common tasks

            

            

              
Find one event among hundreds
Type into the filter box. It matches the domain, path, full URL, and every decoded query and payload value — so checkout or purchase both work.

              
Narrow to one vendor
Use the services dropdown beside the filter box. It lists only the services actually seen in this session, with counts.

              
See only what is broken
Click the red failing button, or press f. The count beside it is the number of requests with at least one failing check.

              
Read a deep payload value
Open the Payload tab and search. Matching branches expand automatically. Hover a row for Copy value and Copy path — the copied path is the same syntax validation rules use.

              
Capture bodies the network layer cannot see
Turn on page hooks in the Allowlist dialog. This is what recovers Adobe WebSDK and sendBeacon payloads. Hooks only run while a session is active, and only report requests matching your allowlist.

              
Share a result
Press c to copy one payload, or use Export validation report for a printable summary of every check in the session.

              
Switch theme
The icon left of Help cycles system → light → dark. The choice is remembered on this machine.

            

          


          

            

              
Validation rules

              
A validation rules file is JSON that describes what a correct analytics call looks like. Import one per site, turn on Run validations when starting a session, and every captured request is checked as it arrives.

            

            

              
Anatomy of a rule

              
conditionsWhen this rule applies. If they do not match, the rule is skipped rather than failed.

              
validationsWhat must be true. All of them must pass.

              
scoperequest checks one call; page counts matching calls per page view.

              
sourcepayload, query, headers or raw. Defaults to payload.

              
pathDotted path with bracket indexes, e.g. events[0].xdm.eventType. Copy Path in the Payload tab gives you this.

            

            

              
Operators

              
exists · not_exists · equals · contains · starts_with · ends_with · regex · in · not_in · gt · gte · lt · lte · range

            

            

              
Getting started

              
Open Validation Rules, click Download template, edit it, then import. The file is checked on import — unknown operators, unknown sources, bad regexes, duplicate rule ids and malformed ranges are reported with the rule number, rather than silently failing every request later.

            

            

              
Reading results

              
passEvery applicable check passed.

              
failAt least one applicable check failed. Click See results for the expected and actual values.

              
no checksNo rule applied to this request. Not a failure.

            

          


          

            

              
Troubleshooting

            

            

              
Nothing is being captured
Check the header pill says Recording. Then confirm the domain is on your allowlist, and that the session is not locked to a different tab than the one you are using.

              
Requests appear but the payload is empty
Some calls send their body in a way the network layer cannot read — WebSDK and sendBeacon especially. Turn on page hooks in the Allowlist dialog and reload the page.

              
Page hooks are on but bodies are still missing
A strict Content-Security-Policy on the site can block hook injection. On Firefox this is more common, because its build cannot inject into the page's own JavaScript context; use the Chrome or Edge build for the most reliable capture.

              
Every rule is failing
Usually the path is wrong. Select a request, open the Payload tab, find the field, and use Copy path — that is exactly the string the rule needs.

              
The session stopped by itself
Sessions end after 5 minutes without a captured request, or when this window closes. Captured data is kept; start a new session to continue.

              
Oldest requests disappeared
A session keeps the most recent 2,000 requests. If browser storage fills up, the oldest half is dropped and you are told — export anything you need to keep.

            

          


          

            

              
FAQ

            

            

              
Does this change or block any request?
No. It only observes. Validation rules classify what was already sent; they never alter it.

              
Is any of this sent anywhere?
No. Captures stay in this browser's local storage, and the extension makes no network requests of its own.

              
Can I reuse one rules file across sites?
Yes — import the same file for each site. Rules are stored per site so they can diverge later.

              
Are values decoded?
Yes. URL-encoding is decoded and + becomes a space, but key and value casing is never changed.

              
Why does a request show "no checks"?
No rule's conditions matched it — for example a rule scoped to Adobe Edge seeing a Google Analytics call. That is expected, not a failure.

              
What do the two-letter badges mean?
The service a domain belongs to, coloured by vendor. Unrecognised domains fall back to initials of the hostname; map them to a service in the Allowlist dialog.

              
Can I run two sessions at once?
No. One session records at a time, so a request is never ambiguous. Switching sessions pauses the previous one.
